# Orbs page parity captures

Reference captures for the `/orbs` page at 1440x900 and 390x844.

- `web-*` are Chrome headless captures of the built `web-baseline` fork,
  served from `sites/home/dist` on a non-localhost hostname so the dev gravity
  panel stays hidden.
- `flutter-*` are Windows Impeller captures from
  `apps/libraries_dev/integration_test/page_capture_test.dart` with the orb
  clock frozen and `TickerMode` disabled.
- `diff-*` are 4x-amplified channel differences.
- `metrics.json` is generated by `tool/compare_parity.py`.

Latest raw metrics:

| Pair | Mean channel delta | p99 | Changed pixels > 8 | 4x downsample |
| --- | ---: | ---: | ---: | ---: |
| 1440x900 | 4.429/255 | 140 | 6.23% | 4.450/255 |
| 390x844 | 8.899/255 | 200 | 12.11% | 8.946/255 |

The captures are a visual review aid, not a pixel gate: Chrome and Impeller
rasterize text and sub-pixel shapes differently. The geometry gate remains
`orbs-golden.json`.

Known layout differences at capture time:

- Flutter's mobile header sits slightly lower than the web because the app
  keeps a small header gap after the docs chip strip.
- The web mobile nav shows a GitHub star-count pill that the Flutter app does
  not yet render.
- The Flutter mobile docs strip starts at Border beam, matching the web; the
  platform row and Copy prompt wrap onto separate rows like the production web.


## Orb matrix

`orb-matrix.json` compares the 144 frozen orb captures
(`9 states x 2 sizes x 2 themes x 4 times`) rendered by the Flutter
`ThinkingOrb` and by the web `sites/orbs/parity.html` harness. Web captures
are transparent, so the comparison composites them over the same page
background as the Flutter captures.

Latest result:

- 144/144 pairs present.
- Mean channel delta: 4.872/255.
- Worst pair mean: 9.093/255 (`shaping-20-dark-0.6`).
- Pairs above 8/255: 33.
- Pairs above 16/255: 0.

Regenerate with the web dev server and:

```sh
python tool/compare_orb_matrix.py
```

`ORBS_WEB_DIR` points at the web PNG directory; the images themselves are
ignored under `reference/captures/`.


## Carousel

`carousel-metrics.json` compares the `/orbs-carousel` page at 1440x900 and
390x844. The Flutter page now uses the production stage (`670x481`, `#070707`
on `#121212`), the same slide order and labels, the same 60px step / 94px rise
diagonal and no extra Previous/Next row. On mobile the stage is anchored left
and clipped by the viewport, matching the production page's overflow.

Latest result:

- 1440x900: mean `0.903/255`, p99 `19`, changed pixels `1.86%`.
- 390x844: mean `2.759/255`, p99 `48`, changed pixels `5.2%`.

Generated by `tool/compare_carousel.py`; the CI parity job enforces a
`5/255` worst-size mean.
