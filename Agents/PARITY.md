# Parity and Verification

## 1. Definition

"Absolute replication" means:

- **Orbs:** identical state set, sizes, presets, geometry, draw order, labels,
  timing, theme behavior, reduced-motion behavior, pause behavior and
  playground content.
- **Orb-related page content:** identical copy, controls, tab order, locked
  states, snippets, prompts and layout structure.
- **Pages:** visual parity within the accepted font, video and rasterizer
  tolerances recorded below.

It does not mean byte-identical screenshots across Chrome and Impeller. The
geometry must be exact; pixels are a calibrated gate.

`orbs-golden.json` contains 72 cases: 9 states x 2 sizes x 4 timestamps, with
70,115 values at 6-decimal precision and `1e-4` tolerance. Dot stride is 6
(`x, y, z, r, white, a`); line stride is 7 (`x1, y1, x2, y2, white, a, w`).

## 3. Geometry gates

### 3.1 Golden vectors

- Run all 72 cases.
- Compare every dot and line value within `1e-4`.
- Compare as an order-independent multiset for `breathing@64`, because the
  centre lane produces mathematically zero-depth ties whose order is not part
  of the rendering contract.
- Assert "same dots, drawn far to near".
- Fail with the exact case, field and expected/actual values.

### 3.2 Preset/spec gates

- Regenerate `spec.g.dart` and require no diff.
- Assert `specVersion` and source library version.
- Assert `resolvePreset` output for every state/size.
- Assert `scaleCounts` and `scaleRadii` behavior.
- Assert `dots`/`dotSize` multipliers and `opts` merge order.

### 3.3 Draw contract

- Lines draw before dots.
- Dots draw in the frame order after `finalizeFrame`.
- Radius floor is the mode's `rMin`.
- Ink ramp preserves the depth shading on tinted orbs.
- No culling or re-sorting in the painter.

## 4. Impeller render matrix

Run on each available Impeller platform:

- 9 states
- 64 and 20 for the official matrix; 32 as an additional smoke case
- dark and light
- timestamps `0.6`, `1.7`, `3.3`, `5.1`
- DPR 2

The runtime painter caps higher device DPRs at a 2x raster; the official
matrix remains DPR 2.

Total official cases: `9 x 2 x 2 x 4 = 144`.

### Important: Impeller vs test goldens

`flutter test` golden files use the software Skia path. They are useful for
layout regressions, but **they are not Impeller evidence**. Impeller captures
must come from a running app on a real Impeller target:

- Android emulator or device
- iOS simulator or device
- Windows desktop
- macOS desktop
- Linux desktop

Capture through an integration test or a debug-only screenshot hook that
writes a deterministic `RepaintBoundary` image. Do not compare against
software-Skia output and call it Impeller parity.

### Reference captures

Generate web reference PNGs from the `web-baseline` worktree with a headless
Chrome/Playwright harness. Freeze the clock at the same four timestamps and
match the canvas size, theme and DPR. Record the browser version and device
scale in the capture manifest.

The Flutter-side matrix is generated by
`apps/libraries_dev/integration_test/orb_capture_test.dart` on a running
Impeller target. On Windows:

```bash
flutter test integration_test/orb_capture_test.dart -d windows
```

Output: `reference/captures/orbs/` (ignored by git). The current Windows run
produced all 144 cases.

### Metrics

For every case, record:

- mean absolute channel difference
- p99 channel difference
- changed-pixel ratio
- centroid delta
- ink-mass ratio
- 4x downsample mean difference

First Impeller baseline: 144/144 pairs, mean 4.872/255, worst 9.093/255
(`shaping-20-dark-0.6`), 33 pairs above 8/255 and none above 16/255. The
comparison composites the web harness PNG over the matching page background;
`tool/compare_orb_matrix.py` writes `reference/parity/orb-matrix.json`.

Raw pixel mean alone is insufficient. A sub-pixel circle bias can look small
while changing the perceived weight of the orb. The existing native ports found
this exact class of residual:

- SwiftUI vs Chrome: worst mean 4.9/255, average 0.90 at 64 and 2.02 at 20.
- React Native/CanvasKit vs Chrome: worst mean 1.4/255.

Use those as context, not as guarantees for Impeller.

### Initial thresholds

These are starting gates; calibrate after the first Impeller baseline and
record every change in this file.

| Case | Mean | p99 | Notes |
| --- | --- | --- | --- |
| 64, dark | <= 3/255 | <= 40/255 | Impeller AA may differ |
| 64, light | <= 3/255 | <= 40/255 | |
| 20, dark | <= 5/255 | <= 60/255 | sub-pixel circle bias |
| 20, light | <= 5/255 | <= 60/255 | |

A threshold change requires:

1. the failed case and metric,
2. a visual review at 1x and 4x,
3. proof that geometry still matches the golden vectors,
4. a note in the deviations table.

Do not average away a failing state. Report the worst case by state and size.

## 6. Motion and behavior gates

- All orbs use the same global clock and stay in phase.
- Speed changes do not reset other orbs.
- Pause freezes the current frame; resume jumps to the current global time.
- Offscreen orbs stop ticking.
- Hidden app or route stops ticking.
- Reduced motion renders the static `t = 0.6` frame.
- Theme changes update ink without restarting geometry.
- Playwright/Pump frames at a fixed `t` match the golden geometry.
- The playground starts paused.
- State/size changes remount the stage as the web does.
- Copy buttons, tabs, locked controls and snippets match.

## 7. Performance gates

- 60fps with four or more simultaneous orbs on a mid-range Android device.
- Orb geometry + paint under 2ms per frame on mid-range mobile.
- Under 1ms per frame on desktop for the same scene.
- No more than one active clock ticker.
- No per-frame allocations in the hot path that profiling shows as significant.
- 13 home-page video tiles must not create 13 simultaneous players; only
  visible tiles play.
- Frame-time results recorded by state, size and platform.

## 8. Accessibility gates

- Each orb exposes an image semantic with the correct state label.
- A label override works.
- Reduced motion is honored live.
- Focus traversal reaches all controls in visual order.
- Copy and tab controls have accessible names and state.
- Text contrast follows the web tokens; known low-contrast web colors are
  documented rather than silently "fixed" if that would break parity.
- Desktop hover-only affordances have keyboard equivalents.
- Touch targets that are smaller than 44dp in the web are documented; do not
  silently grow them if it breaks layout parity.

## 9. Accepted deviations

Record each deviation here with a reason and an owner.

| Deviation | Reason | Status |
| --- | --- | --- |
| Inter replaces Saans | Saans has no license file and is WOFF-only; Inter is approved | Accepted |
| Impeller anti-aliasing differs from Chrome | Different rasterizer | Accepted within thresholds |
| Flutter text layout differs from browser text | Different text engine and fixed-px web sizes | Accepted, masked in page diffs |
| Video frames may differ | Different decoder/timing | Accepted, compare posters where possible |
| Mobile gravity is unavailable | Web requires a fine pointer and a real cursor raster | Accepted, same note as web |
| Windows/Linux cursor sprite may differ from accessibility-enlarged OS cursors | Cursor replacement is restricted | Accepted, disable with note |
| Flutter gravity uses a drawn pointer approximation | The platform cursor raster is not yet ported | In progress, pixel review pending |
| Live npm/GitHub counters are local fixtures in v1 | No network | Accepted |
| Mobile safe areas respect all edges | Web only uses the bottom inset | Accepted |
| No Flutter Web | Product decision | Accepted |
