## Pending

- Local backend remains the default. The real API client is opt-in with
  `--dart-define=USE_REAL_API=true`; it has not been exercised against the
  private Worker without credentials.
- Light theme and theme switching.
- The native MagnetKit engine is not ported. The `/magnetic` page can download
  the licensed model through the real backend, but cannot run it; the bridge
  client expects the external Android bridge APK.
- Metal-fx parity: `MetalFx`/`MetalText` use the Impeller shader and `MetalFx`
  adds a pointer-following light; the Paper reflection paint and full material
  tuning are not ported.
- Image-generation parity: the first pass uses sampled pixel tiles and a
  reveal wave rather than the three.js shader + reveal pipeline.
- Gooey parity: the first pass uses a blur/contrast silhouette rather than the
  SVG filter graph, image melt and DOM measurement engine.
- Bot-avatars full material parity: the Flutter first pass uses vector body
  shapes and a simple gradient material instead of the plastic/fabric
  renderers and full prop surface.
- Border-beam full layer parity: the rotate family now reads `beam-spec.json`
  but still paints in Flutter rather than reproducing the Metal/Swift shader
  layer construction; line/pulse and the color-filter matrix are pending.
- CI has been added but has not run on GitHub yet.
- iOS, macOS and Linux builds are left to CI.
- Store signing, notarization and release credentials are not configured.

```bash
flutter run -d windows --dart-define=START_ROUTE=/orbs
```

## Known deviations

- Saans is replaced by Inter.
- Impeller rasterization differs from Chrome Canvas 2D.
- The rubik base grid for the tuned sizes is generated from JS Math values to
  keep boundary membership stable; other sizes fall back to Dart math.
- Home previews use media_kit MP4 loops on every platform, including touch.
- Gravity uses a Flutter-drawn pointer approximation rather than the platform's
  exact cursor raster; pixel parity is still pending. Use `OrbGravityField`
  around the stage; the `ThinkingOrb.gravity` flag is retained for API
  compatibility but does not attach the field by itself.
